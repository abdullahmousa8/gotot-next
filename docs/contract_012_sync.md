# Contract 012 — Sync (التزامن وعمر الموارد)

| البند | القاعدة | الدليل/السبب |
|---|---|---|
| قائمة الم refreshing | `gpu_hzb_build()` يكتب `view_ubo` (hzb_valid/occ_count/texel_count) **قبل** الـdispatch | 3060-3066 |
| جدولة البناء | `hzb_rebuild_requested = true` ثم البناء داخل submission الرسم نفسه | 3068-3073 |

| ترتيب التحرير | `hzb_pyramid_data_buffer` (1764) يُحرَّر بعد كل uniform sets التي تشير إليه | درس 010: uniforms بعد buffers = «free invalid ID» |
| صفر تواكب | لا كتابة للـbuffer بعد dispatchه | — |

## قاعدة إعادة البناء
`hzb_rebuild_requested` ⇒ **مسرور واحد** يُنتج الهرم كاملاً في نفس الـsubmission؛ لا حلقات CPU على المستويات (SPEC v0.1 §3.1 محفوظ كمتطلب).

## خطر التوقيت (يُوثَّق)
الجسر (B) يقرأ `raster_viewz_texture`؛ إن ثبت أن القراءة قبل الرسم تُرجع أصفاراً (كما يوحي التعليق 3070-3072)، فـ**خيار الجسر الملغى** هو:
- (i) بناء الهرم في **الإطار التالي** من عمق الإطار السابق (temporal-1) — يقبل تأخيراً بإطار، ويلغي حاجة storage view.
- (ii) كتابة viewz إلى مخزن storage من الـfragment shader (يبقى داخل الرسم).
⇒ **قرار معماري مطلوب**؛ يُقاس أولاً (§10).
